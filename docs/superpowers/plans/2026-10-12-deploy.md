# Deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Vārtā deployable as two instances (public demo, Tailscale-only owner) on one VPS. This covers the hardening the demo needs (per-visitor conversations, a chat rate limit), the scheduled worker (sync, news, alerts, briefing, backup, nightly demo reset), container images, Compose + Caddy, and a provisioning runbook. Provisioning itself is done with Tarun.

**Architecture:**
- **One Python image** runs both `api` (uvicorn) and `worker` (a plain scheduler loop). **One web image** is the Next.js standalone build.
- **Compose:** `deploy/compose.yaml` defines `demo` and `owner` profiles; each has its own api/worker/web, env file and data volume. One Caddy container fronts both.
- **Caddy:**
  - Serves the demo on a public domain with automatic TLS, and the owner on the VPS's Tailscale name with a `ts.net` certificate. It binds to the Tailscale IP only.
  - Routes `/api/*` straight to the api container (SSE unbuffered, reliable client IP) and everything else to web.
- **LLM:** both instances use OpenRouter (decision of 2026-10-12, spec §4 note).

**Tech Stack:** Python 3.12 + uv, FastAPI, stdlib sqlite3/zoneinfo/logging, Next.js 16 (`output: "standalone"`), Docker, Docker Compose v2, Caddy 2, Tailscale.

**Spec:** `docs/superpowers/specs/2026-10-11-varta-v2-design.md` §2 (architecture), §3 (sync every 6 h, demo reset nightly), §4 (briefing 07:00, alerts; decision note: OpenRouter for both), §5 (news every 15 min), §6 (demo bar), §7 (deploy, rate limit 20/hour, backups, monitoring).

## Global Constraints

- Polars only (pandas only in `core/prices.py`). Docstrings on every public function and module. Named constants at module top.
- No network or disk side effects at import. Tests never hit the live network.
- Never read, print or log secrets. Never commit `.env`, `*.env` (except `*.env.example` with empty values), `*.db` or `data/`.
- The agent's tools stay read-only; tokens and account numbers never reach the LLM.
- The demo instance can never use Plaid production (already enforced in `Settings`).
- Demo cost guard: per-IP chat rate limit of **20 messages/hour**. The OpenRouter spend cap is set by Tarun on the key (runbook).
- Backups: nightly SQLite online backup, keeping the last **7**.
- Schedules: Plaid sync every **6 h**; news every **15 min**; alerts every **1 h**; briefing daily at **07:00** in `VARTA_TZ` (default `America/New_York`); backup daily at **02:30**; demo reset daily at **03:00** (demo only).
- Conventional Commits, **no `Co-Authored-By`**, never push, never force-push, never run `ruff format` repo-wide.
- Gate: `uv run pytest -q && uv run ruff check .`. For web changes also `cd web && pnpm typecheck && pnpm test && pnpm build`. After any API change, regenerate `web/openapi.json` + `web/lib/api-types.ts`.
- Docker: the daemon is not available on the dev Mac (heat/battery). Verify compose files with `docker compose ... config` (CLI only). Images are built in CI and on the VPS.

## Review Focus

1. **Spoofed client IP:** a client that sends its own `X-Forwarded-For` must not escape the rate limit. Only trust the header when `TRUST_PROXY=1` (set behind Caddy), and then take the **last** hop that Caddy appended. Caddy's default is to overwrite untrusted XFF, so in production the header holds exactly the client IP.
2. **Visitor isolation:** visitor A must never list or read visitor B's conversations, including by guessing a conversation id. When the cookie is missing, the visitor sees no conversations. A chat posted with someone else's `conversation_id` must not append to that conversation.
3. **Demo reset while the API is serving:** reset runs inside the live DB (row deletes in one transaction plus a re-seed), never by replacing the file. Requests during the reset see either the old data or the new data. A failed re-seed leaves an empty DB and logs an error; it must never crash the worker loop.
4. **Worker restart and catch-up:** after a restart, a job that is overdue runs once, not once per missed interval. A job that raises is logged, and the other jobs still run.
5. **Owner exposure:** the owner site must not be reachable on the public IP. Caddy's owner listener (container 8443) is published only on `OWNER_TS_IP`, and no compose port maps any api or web container to the host.

### Task 3: JSON logs and the scheduled worker

**Files:**
- Create: `api/logs.py`, `worker/__init__.py`, `worker/schedule.py`, `worker/main.py`, `scripts/backup_db.py`, `scripts/reset_demo.py`, `tests/test_logs.py`, `tests/test_schedule.py`, `tests/test_worker.py`, `tests/test_reset_demo.py`, `tests/test_backup.py`
- Modify: `api/main.py` (call `setup_logging()` once in `create_app`)

**Interfaces:**
- `api/logs.py`:
  - `class JsonFormatter(logging.Formatter)`: one JSON object per line with keys `ts` (UTC ISO), `level`, `logger`, `msg`, plus `exc` when exc_info is set.
  - `setup_logging(level="INFO") -> None`: idempotent; replaces the root handlers with a single stderr handler using JsonFormatter.
- `worker/schedule.py` (pure, no I/O):
  - `@dataclass(frozen=True) class Job: name: str; every: timedelta | None = None; at: time | None = None; demo_only: bool = False`. Exactly one of `every`/`at` is set; `at` is a local wall-clock time in `tz`.
  - `JOBS: tuple[Job, ...]` = sync (every 6 h), news (every 15 min), alerts (every 1 h), briefing (at 07:00), backup (at 02:30), demo_reset (at 03:00, demo_only).
  - `due(job, now: datetime, last_run: datetime | None, tz: ZoneInfo) -> bool`:
    - `every`: due if `last_run` is None or `now - last_run >= every`.
    - `at`: due if today's local `at` has passed and `last_run` is before today's local `at` (None counts as before).
    - All datetimes are tz-aware UTC; convert with `tz` for `at`.
  - Catch-up is naturally once: one stale `last_run` means one run.
- `worker/main.py`:
  - `run_job(name, settings, now) -> None` dispatches:
    - `sync`: `api.sync.sync_all` over the configured Plaid; skip with an info log if Plaid is not configured.
    - `news`: `scripts.refresh_news.run(settings, offline=False, now=now)`.
    - `alerts`: `generate_alerts(conn, default_toolbox(settings, today))`.
    - `briefing`: `make_briefing`; skip if the LLM is not configured.
    - `backup`: `scripts.backup_db.backup(settings.db_path, BACKUP_DIR, keep=7)`.
    - `demo_reset`: `scripts.reset_demo.reset(settings, today)`.
  - `tick(settings, now, runner=run_job) -> list[str]`:
    - Reads last runs from `app_state` keys `job:<name>` (ISO UTC).
    - Runs every due job (skipping `demo_only` on owner) and returns the names it ran.
    - Writes the new `job:<name>` timestamp **after** the attempt, whether it succeeded or raised, so a failing job retries next interval rather than every tick.
    - Logs exceptions with `log.exception`.
  - `main()`: loops forever, calling `tick` then sleeping `TICK_SECONDS = 60`. It uses `Settings.from_env()` and `setup_logging()`; Ctrl-C/SIGTERM exits cleanly.
  - `BACKUP_DIR` comes from env `VARTA_BACKUP_DIR`, default `data/backups`.
- `scripts/backup_db.py`: `backup(db_path, out_dir, keep=7, now=None) -> Path`. Uses `sqlite3.connect(db).backup(dest)` into `out_dir/varta-YYYYMMDD-HHMM.db`, deletes the oldest beyond `keep`, and returns the new path. Has a CLI.
- `scripts/reset_demo.py`: `reset(settings, today) -> dict`.
  - It refuses (raises ValueError) unless `settings.instance == "demo"`.
  - In one transaction it deletes all rows from every table in `api.db.TABLES` except `app_state`, in FK-safe order (children first).
  - It then calls `scripts.seed_demo.seed(settings, source, today)`. `source` is `"sandbox"` if `settings.plaid_configured` (sandbox env enforced), else `"fake"`. If a sandbox seed fails, it falls back to `"fake"` and logs a warning.
  - After seeding it runs news (`refresh_news.run(..., offline=not settings.typesafe_key and not settings.alpaca_key, now=...)`), alerts, and a briefing if the LLM is configured. Each step is wrapped so that one failure doesn't stop the rest.
  - It returns `{"source": ..., "news": ..., "alerts": n, "briefing": bool}`. Has a CLI.

    - DST: on the spring-forward day, 07:00 still triggers once.

**`deploy/compose.yaml`** (Compose v2):
- YAML anchors `x-api`/`x-web`. The python image is `varta-api` (built from `..`), the web image `varta-web` (built from `../web`).
- Services:
  - `api-demo`, `worker-demo` (same image; `command: ["python", "-m", "worker.main"]`), `web-demo`, all with `profiles: [demo]`.
  - `api-owner`, `worker-owner`, `web-owner`, all with `profiles: [owner]`.
  - `caddy` with `profiles: [demo, owner]`.
- Env files: `demo.env` / `owner.env`, plus `environment` overrides:
  - api: `VARTA_INSTANCE`, `TRUST_PROXY=1`.
  - web: `API_URL=http://api-<inst>:8000`, `VARTA_INSTANCE`.
- Volumes: `demo-data:/data`, `owner-data:/data`, `caddy-data`, `caddy-config`.
- **No `ports:` on api or web.** Caddy is the only container with published ports. A container on the compose bridge network cannot `bind` the host's Tailscale IP, so the split is done at publish time:
  - `"${PUBLIC_IP}:80:80"` and `"${PUBLIC_IP}:443:443"` serve the demo (and the ACME HTTP challenge).
  - `"${OWNER_TS_IP}:443:8443"` serves the owner: Caddy's owner site listens on container port 8443, and the host publishes it **only** on the Tailscale IP.
  - `PUBLIC_IP` and `OWNER_TS_IP` come from `caddy.env`, passed with `--env-file deploy/caddy.env` for interpolation.
  - Caddy mounts `/var/run/tailscale/tailscaled.sock` (read-only) so it can fetch the `ts.net` certificate for `OWNER_HOST`.
- `restart: unless-stopped` everywhere. Healthchecks on api.

**`deploy/Caddyfile`:**

```
{
	email {$ACME_EMAIL}
}

{$DEMO_DOMAIN} {
	handle /healthz {
		reverse_proxy api-demo:8000
	}
	handle /api/* {
		reverse_proxy api-demo:8000 {
			flush_interval -1
		}
	}
	handle {
		encode zstd gzip
		reverse_proxy web-demo:3000
	}
}

{$OWNER_HOST}:8443 {
	handle /api/* {
		reverse_proxy api-owner:8000 {
			flush_interval -1
		}
	}
	handle {
		reverse_proxy web-owner:3000
	}
}
```

- `encode` sits only inside the web `handle`, so the `/api/*` SSE stream is never compressed or buffered.
- When only one profile runs, the other site's upstream is unresolved; that only errors per request, which is acceptable. Document it.
- `OWNER_HOST` is the VPS's MagicDNS name (`<host>.<tailnet>.ts.net`); Caddy fetches its certificate from the tailscaled socket.
