# Advisor Agent + Evals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the Vārtā advisor: a hand-written, read-only tool loop over an OpenAI-compatible API, streamed to the web chat over SSE, plus rule-based alerts, a daily briefing, and an eval harness that compares a local Ollama model with an OpenRouter model.

**Architecture:** `api/agent_tools.py` exposes 12 read-only tools. They reuse the existing finance and news route handlers by looking each one up by path on its router, and add `core/risk.py` for portfolio risk. `api/agent.py` runs the loop: model call, tools, append results, at most 8 rounds, then a forced answer. It yields events that `/api/chat` turns into SSE. Alerts and the briefing reuse the same toolbox. `evals/` builds a deterministic fixture DB, runs YAML tasks through the same `run_agent`, records the runs, and checks them deterministically; CI replays the recordings.

**Tech Stack:** Python 3.12, FastAPI, `openai` SDK (new dependency), Polars, stdlib sqlite3, PyYAML (dev only), Next.js 16 / React 19, node:test.

**Spec:** `docs/superpowers/specs/2026-10-11-varta-v2-design.md` §4 (agent), §6 (UI), §7 (testing).

## Global Constraints

- Polars only (pandas only in `core/prices.py`). A docstring on every public function and module. No magic numbers: name constants at module top.
- No network or disk side effects at import. Tests never touch the live network: the LLM is faked with scripted responses.
- Tools are read-only. Never pass Plaid tokens, `account_id`s or account masks/numbers to the LLM.
- Never read, print or log secrets; never commit `.env`, `*.db` or `data/`.
- Models are set in config (`LLM_BASE_URL`, `LLM_MODEL`), never in code.
- No LangChain or LangGraph. The loop is hand-written with the `openai` SDK.
- Conventional Commits, **no `Co-Authored-By` line**, never force-push. Never run `ruff format` repo-wide; format only the files you touched, or not at all.
- `uv run pytest -q && uv run ruff check .` pass before every commit. Web: `cd web && pnpm typecheck && pnpm test && pnpm build`.
- Any API change: `uv run python -m scripts.dump_openapi` then `cd web && pnpm gen:api`, and commit both (the snapshot test enforces this).
- Verify `openai` SDK names against the installed version (`uv run python -c "import openai; print(openai.__version__)"`) before relying on them.

## Review Focus

1. **The model sends a bad tool call** (unknown name, invalid JSON args, wrong types, out-of-range days): the tool returns `{"error": ...}` to the model and the loop continues. No 500, no stream that never ends.
2. **The LLM backend is down, times out or is not configured:** `/api/chat` returns 503 when unconfigured. If it fails mid-stream, the client gets an `error` SSE event and the user message is still logged.
3. **The model keeps calling tools:** after 8 rounds one final call is made without tools, and its text is the answer.
4. **Empty DB (no accounts linked, no news):** every tool returns empty lists or zeros, and the context header still builds (regime failure included).
5. **A citation to an id that was not in this turn's `get_news` results:** it is not returned as a source, and evals fail it.

```python
"""Portfolio risk metrics: annualized volatility, max drawdown and beta. Pure Polars."""

import math

import polars as pl

TRADING_DAYS = 252


def portfolio_risk(closes: pl.DataFrame, weights: dict[str, float],
                   benchmark: str = "SPY") -> dict:
    """Risk of a weighted portfolio from long-format closes [date, ticker, close].

    Weights are renormalized over tickers that have prices; covered_weight says how
    much of the original weight that was. Beta is None without benchmark variance.
    """
    wide = closes.pivot(on="ticker", index="date", values="close").sort("date")
    tickers = [c for c in wide.columns if c != "date"]
    # ponytail: rows with any missing close are dropped; per-pair alignment if histories differ a lot
    rets = wide.select(pl.col(t).pct_change() for t in tickers).slice(1).drop_nulls()
    held = [t for t in weights if t in rets.columns and weights[t] > 0]
    if not held or rets.height == 0:
        raise ValueError("no price history for any holding")
    covered = sum(weights[t] for t in held)
    port = rets.select(sum(pl.col(t) * (weights[t] / covered) for t in held).alias("p"))["p"]
    equity = pl.concat([pl.Series([1.0]), (port + 1).cum_prod()])  # start at 1.0
    drawdown = float((equity / equity.cum_max() - 1).min())
    beta = None
    if benchmark in rets.columns:
        bench = rets[benchmark]
        var = float(bench.var())
        if var > 0:
            beta = float(pl.DataFrame({"p": port, "b": bench}).select(pl.cov("p", "b")).item()) / var
    vol = float(port.std() or 0.0) * math.sqrt(TRADING_DAYS)
    return {"volatility": round(vol, 4), "max_drawdown": round(min(drawdown, 0.0), 4),
            "beta": None if beta is None else round(beta, 3),
            "covered_weight": round(covered, 4), "days": rets.height}
```

**Loop (reference implementation):**

```python
def run_agent(client, model: str, messages: list[dict], toolbox: Toolbox,
              clock: Callable[[], float] = time.monotonic) -> Iterator[dict]:
    """Call the model, run requested tools, repeat; at most MAX_TOOL_ROUNDS tool rounds."""
    start, calls, seen, tin, tout = clock(), [], {}, 0, 0
    answer = ""
    for round_no in range(MAX_TOOL_ROUNDS + 1):
        final = round_no == MAX_TOOL_ROUNDS
        if final:
            messages.append({"role": "user", "content": FORCE_ANSWER})
        resp = client.chat.completions.create(
            model=model, messages=messages, **({} if final else {"tools": toolbox.specs}))
        if resp.usage:
            tin, tout = tin + resp.usage.prompt_tokens, tout + resp.usage.completion_tokens
        msg = resp.choices[0].message
        if final or not msg.tool_calls:
            answer = msg.content or ""
            break
        messages.append({"role": "assistant", "content": msg.content or "", "tool_calls": [
            {"id": tc.id, "type": "function",
             "function": {"name": tc.function.name, "arguments": tc.function.arguments}}
            for tc in msg.tool_calls]})
        for tc in msg.tool_calls:
            args = _safe_args(tc.function.arguments)
            yield {"type": "tool", "name": tc.function.name, "args": args}
            calls.append({"name": tc.function.name, "args": args})
            result = toolbox.call(tc.function.name, tc.function.arguments)
            if tc.function.name == "get_news":
                seen.update({i["id"]: i for i in result.get("items", [])})
            messages.append({"role": "tool", "tool_call_id": tc.id,
                             "content": json.dumps(result, separators=(",", ":"))})
    cited = dict.fromkeys(int(m) for m in CITATION_RE.findall(answer))
    yield {"type": "answer", "text": answer}
    yield {"type": "done", "tool_calls": calls, "model": model,
           "sources": [_source(seen[i]) for i in cited if i in seen],
           "tokens_in": tin, "tokens_out": tout,
           "latency_ms": round((clock() - start) * 1000)}
```

`FORCE_ANSWER = "Answer now using only the data you already have."` `_safe_args` returns the parsed dict, or `{}` on bad JSON. `_source(item)` returns `{"id","title","source","published_at"}`.

**Ruling (carried from planning):** the answer arrives as one `answer` event rather than token by token. Tool progress streams live. Token streaming with tool calls is inconsistent across Ollama and OpenRouter models; a later change can add `stream=True` to the final call only.

### Task 7: Eval harness (deterministic part)

**Interfaces:**
- Consumes: `scripts.seed_demo.seed`, `scripts.refresh_news.run`, `build_toolbox`, `build_messages`, `run_agent`, `llm_client`, `Regime`.
- Produces:
  - `evals.fixture_db`: `EVAL_TODAY = date(2026, 10, 12)`, `EVAL_NOW = datetime(2026, 10, 12, 12, tzinfo=UTC)`, `EVAL_REGIME = Regime(label="Elevated", prob=0.55, brent_vol=0.42, spy_dd=-0.06, gold_oil=36.5, signals={"vol_score": 0.6, "dd_score": 0.4, "gold_oil_score": 0.5})`.
    - `synthetic_closes(tickers) -> pl.DataFrame`: a seeded (`CLOSES_SEED = 7`) 252-day random walk per ticker, starting at 100.
    - `build(path: Path) -> Path`: `seed(Settings(db_path=path, instance="demo", token_key=new_key()), "fake", EVAL_TODAY)` then `refresh_news.run(..., offline=True, now=EVAL_NOW)`.
    - `eval_toolbox(path) -> Toolbox`.
  - `evals.checks`: `parse_numbers(text) -> list[float]`, `check_task(task: dict, rec: dict, conn) -> list[str]` (the failure messages; empty = pass).
  - Recording JSON shape (one file per task: `evals/recordings/<model-slug>/<task-id>.json`): `{"task_id","model","answer","tool_calls":[{"name","args"}],"sources":[{"id",...}],"latency_ms","tokens_in","tokens_out","cost_usd"}`. `model-slug` = the model id with `/` and `:` replaced by `_`.

**Task YAML shape:**

```yaml
- id: bills-this-week
  question: What bills are due this week?
  tools: [get_upcoming_bills]          # all must be called
  numbers:                              # each must appear in the answer (within tolerance)
    - sql: "SELECT ROUND(SUM(last_amount),2) FROM recurring_streams WHERE is_active=1 AND predicted_next_date BETWEEN '2026-10-12' AND '2026-10-19'"
      rel: 0.01                         # optional, default 0.01
  cite: false                           # true → at least one [n:ID] citation required
  no_amounts: false                     # true → the answer must contain no $ amount
  forbid: []                            # case-insensitive substrings that must not appear
```

**Checks (`check_task`):**
- **tools:** every `tools` name is in the recorded call names.
- **numbers:** run each `sql` (a scalar). It passes if some number parsed from the answer is within `max(rel*|v|, ABS_TOL=0.5)` of v. If the SQL returns NULL, the task itself is wrong: report "ground truth is null".
- **tickers:** every `\b[A-Z]{2,5}\b` token in the answer is either in `ALLOWED_CAPS` (US, USD, ETF, APR, APY, CPI, GDP, FOMC, FED, AI, OK, IRA, LLC, SEC, EPS, YTD, ATM, FDIC, CEO, NYSE, NASDAQ, PM, AM, EST, ET, TV, NOTE, ALL, MARKET) or in the DB tickers (`securities.ticker` ∪ every `news_items.tickers` value).
- **citations:** every `[n:ID]` id exists in `news_items` *and* is in the recording's `sources` ids; `cite: true` needs at least one.
- **no_amounts:** `re.search(r"\$\s?\d", answer)` is None.
- **forbid:** none of the substrings is present.
- `parse_numbers` handles `$2,450.00`, `-1,240.55`, `86%`, `11.58`, `$96`. It strips `$`, `,` and `%` (a percentage stays as its number, so tasks with percentages give the SQL value ×100).

**Runner (`python -m evals.run`):**
- `--model ID --base-url URL [--api-key-env NAME] [--price-in USD_PER_MTOK --price-out USD_PER_MTOK] [--only TASK_ID]`.
  - Builds the fixture DB in a temp dir and runs each task as a fresh conversation: `build_messages(toolbox, [], question)` → `run_agent`.
  - Writes the recordings. Cost = tokens × prices / 1e6, or 0.
  - Prints per-task pass/fail and the failure messages.
  - The key is read from the env var named by `--api-key-env`; it is never printed.
- `--report`: reads all recordings, re-checks them against a fresh fixture DB, and writes `evals/RESULTS.md`. That file has a table per model (tasks, passed, pass rate, p50 / p95 latency ms, mean tokens in/out, total cost USD) and then a per-task pass matrix (task × model, ✓ / ✗).
- Model ids come only from the CLI, never hard-coded.
