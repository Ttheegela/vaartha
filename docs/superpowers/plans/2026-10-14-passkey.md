# Passkey Lock + Dock App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lock the owner instance behind a passkey (Touch ID on the Mac, Face ID on the iPhone via iCloud Keychain), with a 15-minute idle auto-lock. Make Vārtā installable as a Dock / home-screen web app. The public demo stays open.

**Architecture:**
- **API, owner only:** WebAuthn registration and authentication through `py_webauthn`.
  - Credentials (public keys) are stored in SQLite.
  - Server-side sessions use a random token. Only its SHA-256 is stored, and the browser holds it in an `HttpOnly; Secure; SameSite=Strict` cookie `varta_session`.
  - Middleware rejects every `/api/*` request without a live session, except `/api/auth/*`. `/healthz` stays open.
- **First registration** needs a one-time setup code that only someone at the Mac can produce, via a CLI.
- **Web:** a `/lock` page uses `@simplewebauthn/browser`.
  - `proxy.ts` sends cookie-less page requests to `/lock`, and server-side `apiGet` forwards the session cookie.
  - A 401 from the API redirects to `/lock`.
  - A client idle timer locks after 15 minutes.
- **One web address:** passkeys are bound to one origin, the Tailscale HTTPS URL, so on the owner instance the proxy sends `localhost` to that URL.
- **Dock / home-screen app:** a web app manifest plus generated icons. Install it with Safari's Add to Dock or Add to Home Screen.

**Tech Stack:**
- Python: `webauthn` 3.0.1 (py_webauthn, Duo Labs). Verify the API against the installed version.
- Web: `@simplewebauthn/browser` 14.0.0. Verify against the installed version.
- Framework: FastAPI middleware, stdlib `secrets` and `hashlib`, Next.js 16 `proxy.ts`, `app/manifest.ts` and `app/apple-icon.tsx` (ImageResponse).

**Spec:** CLAUDE.md rules. Design agreed in chat on 2026-10-14:
- Passkey lock on the owner instance, auto-lock 15 min idle.
- One-time setup code from the Mac.
- CLI reset for recovery.
- Server-enforced on every API route.
- Demo unaffected.
- The Tailscale URL is the canonical origin.

## Global Constraints

- **Where the lock applies:**
  - `auth_required` is true **only** when `VARTA_INSTANCE=owner`, unless `OWNER_AUTH=0` is set explicitly (escape hatch for local dev). Demo behaviour and tests are unchanged.
  - When `auth_required`, startup **fails closed** if `PASSKEY_RP_ID` or `PASSKEY_ORIGIN` is missing. The origin must be `https://`, except `http://localhost`, which is allowed for local dev.
- **Constants:**
  - Idle timeout `AUTH_IDLE_MINUTES` = 15 (env-overridable).
  - Absolute session max `AUTH_MAX_HOURS` = 12.
  - Setup code TTL `SETUP_CODE_MINUTES` = 10, 8 characters from an unambiguous alphabet.
  - Challenge TTL `CHALLENGE_SECONDS` = 300.
- **Never log or print** session tokens, challenges, setup codes (except the CLI's single stdout line meant for the user), or credential public keys. Never commit `.env`, `*.db` or any `owner.env`.
- **Usual project rules:**
  - TDD with RED captured. Polars only. Docstrings, named constants.
  - No network in tests. Never start Docker. Never run `scripts/owner.sh start`.
  - Conventional Commits, **no Co-Authored-By**, no push.
  - Gate: `uv run pytest -q && uv run ruff check .`, then `cd web && pnpm typecheck && pnpm test && pnpm build`. Regenerate the OpenAPI snapshot and web types when the API changes.

## Review Focus

1. **Bypass:** any `/api/*` route other than `/api/auth/*` must return 401 without a valid, unexpired session on the owner instance. This covers SSE chat, Plaid link and exchange, sync, alerts dismiss and link_event. Server-rendered pages must not leak data when the API returns 401.
2. **Registration takeover:** registering a passkey always requires a valid, unexpired, single-use setup code, including when credentials already exist. Codes are compared in constant time and stored hashed.
3. **Replay and phishing:** each challenge is single-use and expires. The RP ID and expected origin come from settings, never from the request. The sign count is updated, and a regression is rejected per py_webauthn.
4. **Session hygiene:**
   - The token is random (32 bytes) and stored hashed.
   - Idle expiry slides on each authenticated request. The absolute cap is enforced.
   - Logout deletes the session server-side.
   - The cookie carries `HttpOnly`, `Secure` (whenever the origin is https) and `SameSite=Strict`.
5. **Demo and tests unaffected:** with `instance=demo`, no auth middleware runs and no auth cookie is required. All existing tests pass unchanged.

### Task 1: Passkey auth API (owner only)

**Files:**
- Create: `api/auth.py` (router + session middleware + helpers), `scripts/passkey.py` (CLI: `setup-code`, `reset`, `list`), `tests/test_auth.py`
- Modify:
  - `api/settings.py`: `auth_required`, `passkey_rp_id`, `passkey_origin`, `passkey_rp_name` (default "Vārtā"), `auth_idle_minutes`
  - `api/schema.sql` and `api/db.py`: new tables, added to `TABLES`
  - `api/main.py`: include the router and register the middleware only when `auth_required`
  - `pyproject.toml` and `uv.lock`: `uv add webauthn`
  - `web/openapi.json`, `web/lib/api-types.ts`

**Tables:**
- `auth_credentials(credential_id TEXT PRIMARY KEY, public_key BLOB NOT NULL, sign_count INTEGER NOT NULL, transports TEXT, created_at TEXT NOT NULL, last_used_at TEXT)`
- `auth_sessions(token_hash TEXT PRIMARY KEY, created_at TEXT NOT NULL, last_seen_at TEXT NOT NULL)`
- `auth_challenges(challenge TEXT PRIMARY KEY, kind TEXT NOT NULL, expires_at TEXT NOT NULL)`

The setup code is stored as `app_state` key `auth:setup_code`, holding the sha256 hex and its expiry as JSON.

**Endpoints** (prefix `/api/auth`, JSON):
- `GET /status` returns `{auth_required, authenticated, has_credentials}`.
- `POST /register/options` with body `{setup_code}`.
  - A valid code returns PublicKeyCredentialCreationOptions JSON (py_webauthn `options_to_json`) and stores the challenge (kind=register).
  - The `rp.id` and `rp.name` come from settings. `user.id` is a fixed per-instance handle (random 16 bytes kept in `app_state`, generated once).
  - `residentKey` is `required` and `userVerification` is `required`.
  - Excluded credentials are the existing ones.
  - An invalid or expired code returns 403.
- `POST /register/verify` with body `{setup_code, credential}`.
  - It re-checks the code, verifies against the stored challenge, the expected origin and the RP ID, and stores the credential.
  - It **consumes** the code and challenge, then creates a session (sets the cookie).
- `POST /login/options` returns RequestOptions with `userVerification: required`. `allowCredentials` is empty, so discoverable credentials are used. The challenge is stored with kind=login.
- `POST /login/verify` with body `{credential}`.
  - It looks up the credential, verifies it, updates sign_count and last_used_at, consumes the challenge, and creates the session.
  - An unknown credential or a failed verification returns 401.
- `POST /logout` deletes the session row and clears the cookie, then returns 204.

**Middleware** (only when `auth_required`):
- Paths starting with `/api/` but not `/api/auth/` need a cookie `varta_session` whose sha256 matches an `auth_sessions` row with `now - last_seen_at < idle` and `now - created_at < max`. Then `last_seen_at` is updated (sliding).
- Otherwise it returns 401 `{"detail": "locked"}`.
- `/healthz` and non-`/api` paths pass. The API serves no pages.
- Use an injectable `clock` for tests.
- The session cookie is `HttpOnly`, `SameSite=Strict`, `Path=/`, and `Secure` when `passkey_origin` starts with https. It has no Max-Age, so it's a session cookie; the server enforces expiry.

**CLI** (`python -m scripts.passkey`, using `Settings.from_env()`):
- `setup-code` generates a code, stores the hash and expiry, and prints exactly one line: `Setup code (valid 10 min): XXXX-XXXX`.
- `reset` deletes all credentials and sessions after asking `type RESET to confirm`; `--yes` skips the prompt.
- `list` prints a count and the created/last-used dates, never key material.

**Tests** (no real authenticator):
- Monkeypatch `webauthn.verify_registration_response` and `verify_authentication_response`, or wrap them behind module-level functions in `api/auth.py` that tests replace.
- Cover:
  - status on owner and on demo
  - `register/options` with no code, a bad code, an expired code (fake clock) and a valid code
  - `register/verify` consumes the code: a second use returns 403
  - a challenge can't be reused
  - login success sets the cookie with `HttpOnly`, `Strict` and `Secure`
  - an unknown credential returns 401
  - the middleware returns 401 for `/api/accounts`, `/api/chat`, `/api/plaid/link_token` and `/api/sync` without a cookie, and 200 with one
  - idle expiry at 15 min (fake clock) and the absolute 12 h cap
  - sliding refresh
  - logout invalidates
  - demo: the middleware is absent, `/api/accounts` works with no cookie, and existing tests are untouched
  - startup fails when `auth_required` and the RP ID or origin is missing, or the origin is http and not localhost
  - the CLI `setup-code` output format, `reset --yes` and `list`, with no secrets printed
- The test suite constructs `Settings(instance="owner", ...)` explicitly where needed. Existing owner-instance tests must pass `OWNER_AUTH`-equivalent settings (`auth_required=False`), or they will start failing; update them minimally and say so in the report.

- [ ] Write the failing tests. Run them and see them fail. Implement. Run the full gate. Commit with `feat(auth): passkey lock for the owner instance`.

### Task 2: Web lock screen

**Files:**
- Create: `web/app/lock/page.tsx` and a client component `web/components/passkey-lock.tsx`, `web/lib/idle.ts` (pure idle-timer logic) with `web/tests/idle.test.ts`
- Modify:
  - `web/proxy.ts`: owner auth redirect and canonical origin
  - `web/lib/server-api.ts`: forward `varta_session`, 401 → `redirect("/lock")`
  - `web/app/layout.tsx` or `web/components/app-shell.tsx`: idle timer and a Lock button when `VARTA_AUTH=1`
  - `pnpm add @simplewebauthn/browser@14`

**Behaviour:**
- **Web env:**
  - `VARTA_AUTH=1` turns the lock UI on. `owner.sh` sets it from `OWNER_AUTH`, default on.
  - `PASSKEY_ORIGIN` is the canonical origin.
  - The demo sets neither.
- **proxy.ts** (keep the existing https redirect logic):
  - When `VARTA_AUTH=1` and the request host differs from `PASSKEY_ORIGIN`'s host, redirect (308) to the same path on `PASSKEY_ORIGIN`.
  - When the request is not `/lock`, has no static or `/api` path, and has no `varta_session` cookie, redirect to `/lock?next=<path>`. Validate `next` as a same-site relative path.
  - The proxy only checks that the cookie is present; the API validates it.
- **server-api.ts:** `apiGet` forwards `varta_session` (read via `cookies()`, validated as a URL-safe token shape) along with `varta_vid`. On a 401 it calls `redirect('/lock')`, which must not be caught as an error. All server pages keep working on the demo, where no cookie exists.
- **/lock page:**
  - Shows the Vārtā mark and a primary button **"Unlock with Touch ID"**, which runs `startAuthentication(optionsJSON)` → `/api/auth/login/verify` → navigate to `next` or `/`.
  - If `has_credentials` is false, it shows **"Set up your passkey"** with an 8-character setup-code input and the hint "Run `python -m scripts.passkey setup-code` on your Mac". That runs `startRegistration` → verify → navigate.
  - Errors map to plain messages: cancelled, no passkey on this device (offer setup), locked.
  - Browser calls use `apiUrl` and `credentials: "include"`.
- **Idle auto-lock:** `web/lib/idle.ts` exports `createIdleTimer({timeoutMs, now, onIdle})`, pure and testable with a fake clock. The app shell resets it on pointer, keyboard, scroll and visibility. On idle it calls `POST /api/auth/logout` and then `location.assign('/lock')`. The 15-min value comes from a constant matching the API default.
- **Lock button:** in the sidebar footer near Settings, owner only. It calls logout and goes to `/lock`.

- [ ] Write failing node tests for `idle.ts` (fires after the timeout, reset defers, stop cancels) and for any pure helpers such as the `next` path validation. Implement. Run `pnpm typecheck && pnpm test && pnpm build`. Commit with `feat(web): passkey lock screen and idle auto-lock`.
